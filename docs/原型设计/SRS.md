# 竞赛社团管理平台 · 需求规格（原型）

> **读者**：想知道「当初定成了什么、明确不做什么」的人，以及接手这个平台的 AI。
> **本文档于 2026-10-12 冻结**，记录的是 `v1.4.0`（2026-10-10）那一刻的样子。现状见
> [`../更新维护/`](../更新维护/) 与代码——**冲突时以后两者为准**。

**本文档不设需求编号。** 需求随迭代长，编号会先烂掉——所以每条需求直接指向
**代码坐标**（模块路径、公开函数、用例模块），而不是 `REQ-xxx`。这一条从
2026-10-10 起就是本项目的口径，倒回编号体系没有引用方。

## 1. 目的与范围

面向竞赛社团的轻量管理平台，**单台服务器**部署。以成员视角为核心，三个面：

- **公开门户**：访客无需登录即可浏览社团简介、历年获奖、成员风采、公开公告。
- **成员系统**：登录后进入成员界面，查看内部通知与「我的消息」、个人信息、项目组、
  竞赛报名、设备借用、社团空间。
- **管理后台**：管理员发布公开／内部通知、发布竞赛、管理账号与设备、查看各类登记汇总、
  处理创建项目组申请与评审改派。

**核心原则**：单体应用、模块化拆分、权限收敛到统一的一层、操作入口可插拔。

**范围**：从「管理员发账号」到「项目书评审归档」的社团日常运转闭环，不含对外 API。

## 2. 不做什么

➥ 需求一直会变，但**被否掉的路不该被重新走一遍**——这些是有意不做，不是还没做。

| 不做的事 | 理由 |
|---|---|
| 开放注册、自助找回密码 | 成员由管理员发放账号，忘密码找管理员重置：社团规模下这样最省事，也避免陌生人建号 |
| 报名审批、借用审批 | 登记即生效；加审批要引入状态机与待办，而这两件事没有争议性 |
| 为「项目组联系人」建用户组 | 对象身份由 `leader` 计算，存两份必然分叉 |
| 后台身份名册提供对象身份（联系人／组员）的分配入口 | 名册只读；改归属要去项目组页——那才是会走业务校验的路径（名册直接指定会绕过入组审批） |
| 教师账号、把指导老师关联成用户 | 平台没有教师账号体系，指导老师是纯文本姓名 |
| 视频转码／多码率 | 直传 MP4 由 Nginx 直出并支持 Range 拖动；转码要引入 ffmpeg 或对象存储，社团规模不值当 |
| 前台 API（小程序／校园系统） | 当前对外只有页面路由。DRF 曾作为空依赖装过，已按「不留不用的依赖」移除 |
| 引入 HTMX 与富文本编辑器组件 | 交互以整页表单提交为主；页面脚本只做渐进增强，Markdown 在 textarea 里手写、服务端渲染 |
| 后台界面的双语 | 双语只覆盖前台，`/admin/` 固定中文 |
| 审计日志记敏感信息 | 只记非敏感结构化信息，不记密码、Cookie 与完整请求体 |

## 3. 非功能需求

### 3.1 质量目标

按「这个平台最怕什么坏」排序，前五个。它们是取舍时的裁判——两处设计冲突时，
让位给排在前面的。

| # | 目标 | 为什么排这个位置 |
|---|---|---|
| 1 | **权限判定只有一个答案**——判定写在 `permissions.py`，视图门槛走 `core.permissions.require`，「谁算管理员」只问 `is_admin` | 这里管的是实名身份与评审结论；判定分叉就是越权口子，而且分叉了从页面上看不出来 |
| 2 | **受保护件取不到就是取不到**——落在 `mediafiles/` 之外，没有任何 HTTP 路径能直接命中 | 这些文件的可见性由业务规则决定，而 Nginx 直出目录没有规则 |
| 3 | **评审的结论不可改写、身份不泄漏** | 结论决定项目组能否立项／结题；匿名是评审人敢说真话的前提 |
| 4 | **发得出去，也退得回来** | 单台服务器、没有灰度、出问题时维护者多半不在现场 |
| 5 | **测试是「做完了」的判据**——`check` + `makemigrations --check --dry-run` + `test` 三项全绿 | 这套用例是代码里唯一能自动回答「有没有改坏」的东西 |

> **一处测试盲区**：建组申请的并发用例覆盖的是**顺序第二次提交**，**真并发没有用例**——
> 两个管理员同时同意时靠服务层的行锁 + 复查挡住，但没有测试钉住它。

## 4. 约束

➥ **外部给定的、没得选**的前提（不是我们选了什么——那是
[`设计说明.md`](设计说明.md) §2 的事）。

| 约束 | 来源 | 若不满足会怎样 |
|---|---|---|
| 数据库**固定 PostgreSQL**（≥14） | 迁移用到部分唯一索引、`CHECK`、`pg_trgm`、行级触发器 | 审计「只追加」与几组唯一性随之失守 |
| 单台服务器、**没有灰度发布** | 社团的运维条件 | 出问题时只能靠回滚；所以要求任意一版代码与当版数据库兼容 |
| 部署细节不进架构 | 由使用者在自己的服务器上安装 | — |
| 生产走 HTTPS，Nginx 作反向代理与静态服务 | 视频直放与受保护件的目录边界都依赖它 | 受保护件的「没有 HTTP 路径能命中」不再成立 |
| 没有教师账号体系 | 社团没有教师名册 | 指导老师只能是纯文本姓名 |
| 分发的依赖里有 LGPL（psycopg） | 上游许可 | 见 [`../更新维护/许可.md`](../更新维护/许可.md) |
| `pg_trgm` 是**硬依赖** | 历年获奖判重要用它算相似度（迁移 `content.0004_pg_trgm`） | 只装 PostgreSQL server、没装 contrib 的机器上那条迁移会失败 |
| 社团规模：成员与记录量在几百量级 | 分页、缓存、搜索都按这个量级取舍 | 获奖搜索用 `icontains`，量级上去后要换索引方案 |
