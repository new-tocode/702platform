# 阶段二补充验收标准：通知用户组可见性

## 1. 规则

- 公开通知：访客、所有成员都可以查看，不配置用户组。
- 内部通知：必须至少绑定一个 Django 用户组。
- 用户属于通知绑定的任意一个用户组即可查看。
- 用户不属于任何绑定组时不可查看。
- 未登录访客不可查看内部通知。
- 尚未完成首次改密的登录用户仍然不可查看内部通知。
- 列表和详情都执行后端权限过滤；未授权详情返回 404。

## 2. Admin 验收

- 通知表单新增“可查看用户组”多选项。
- 内部通知不选择用户组时不能保存。
- 公开通知选择用户组时不能保存。
- 通知列表显示可查看用户组。
- 管理员发布通知时自动记录发布人。

## 3. 自动化验收

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py migrate
.venv/bin/python manage.py test notices --verbosity 2
.venv/bin/python manage.py test --verbosity 1
```

必须满足：

- Django 检查无错误；
- 无未生成迁移；
- 用户组权限测试全部通过；
- 全量回归测试全部通过。

## 4. 核心测试场景

| 场景 | 预期 |
|---|---|
| 访客访问内部通知列表 | 跳转登录 |
| 访客访问内部通知详情 | 无法访问 |
| 属于选定用户组的成员 | 可见列表和详情 |
| 只属于其他用户组的成员 | 列表不出现，详情 404 |
| 不属于任何用户组的成员 | 列表不出现，详情 404 |
| 属于任一选定组的成员 | 可见 |
| 未完成强制改密的成员 | 跳转改密页 |
| 公开通知配置用户组 | Admin 校验失败 |
| 内部通知未配置用户组 | Admin 校验失败 |
