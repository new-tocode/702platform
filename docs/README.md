## 为什么这么分

`architecture/` 按 Django app 拆篇，是因为**改动天然是按 app 发生的**：动评审规则就打开
`reviews.md`，不必在一个 744 行的文件里先翻过 accounts 和 equipment。原先的
`docs/architecture.md` 是单文件，随着评审模块长大，它的「数据模型」一章占了全文一半。

`development.md` 保留单文件：它讲的是**约定**，约定要能一口气读完才有约束力，拆开反而
让人只看一节就以为看全了。它里面不复述架构——`reviews` 那一条验收要点原先有 1787 字符，
把架构文档里同一套规则又讲了一遍，现在压成一句话，细节走链接。

## 文档里不写什么

- **不写能从代码读出来的东西**：函数签名、字段列表的完整枚举。文档写**为什么**这么设计、
  以及**改动时不能破坏什么**。
- **不写过程**：某个功能是哪次提交加的、中间试错了几轮，那是 `git log` 的事。
- **不写会过期的数字**：测试条数、文件行数。要数字就现跑一遍。
