# 阶段二验收标准：公开与内部通知

> 只有本清单中的必选项全部通过，通知模块才算完成。

## 1. 验收范围

阶段二覆盖：

- `notices` Django app 与数据库模型
- 公开通知列表和详情
- 内部通知列表和详情
- 公开首页最新通知
- 置顶通知排序
- 管理员在 Django Admin 发布通知
- 公开/内部可见范围隔离
- 首次改密限制与通知权限联动
- 通知访问、发布日志

阶段二不覆盖通知附件、富文本编辑器、图片/视频上传、分页和站内消息提醒；这些在媒体和后续业务阶段实现。

通知内部可见用户组的补充验收标准见 [`acceptance-notice-groups.md`](acceptance-notice-groups.md)。

## 2. 数据和路由标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| N-01 | `Notice` 模型包含标题、正文、可见范围、置顶、发布人、发布时间和更新时间 | 模型检查/迁移 |
| N-02 | `scope` 只能表示 `public` 或 `internal` | 模型 choices + 测试 |
| N-03 | 通知按置顶、发布时间倒序排列 | 自动测试 |
| N-04 | 公开列表路由为 `/notices/` | 自动测试 |
| N-05 | 公开详情路由为 `/notices/<id>/` | 自动测试 |
| N-06 | 内部列表路由为 `/member/notices/` | 自动测试 |
| N-07 | 内部详情路由为 `/member/notices/<id>/` | 自动测试 |

## 3. 可见性标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| N-08 | 匿名访客可以查看公开通知列表和详情 | 自动测试/人工冒烟 |
| N-09 | 公开列表不显示内部通知 | 自动测试 |
| N-10 | 公开详情访问内部通知返回 404 | 自动测试 |
| N-11 | 匿名访客访问内部通知列表会跳转登录 | 自动测试 |
| N-12 | 已完成改密的成员可以查看内部通知列表和详情 | 自动测试 |
| N-13 | 已完成改密的成员访问公开通知仍只能看到公开内容 | 自动测试 |
| N-14 | 未完成首次改密的成员访问内部通知会被强制带到改密页 | 自动测试 |
| N-15 | 首页只展示公开通知，不泄露内部通知 | 自动测试 |
| N-16 | 首页有“查看全部公开通知”入口 | 模板检查/人工冒烟 |

## 4. 管理员标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| N-17 | 管理员可以在 `/admin/` 新建公开或内部通知 | 自动测试/人工冒烟 |
| N-18 | 新建通知自动记录当前管理员为 `published_by` | 自动测试 |
| N-19 | 普通成员不能进入通知 Admin | 自动测试 |
| N-20 | Admin 可按可见范围、置顶状态、发布时间筛选和搜索通知 | Admin 配置检查 |
| N-21 | 新建/修改通知写入管理员操作日志 | 日志检查 |

## 5. 日志标准

通知访问日志应包含：

- `notice.list.view`
- `notice.detail.view`
- `scope`
- `notice_id`（详情访问）或结果数量（列表访问）
- 当前用户名或 `anonymous`
- `request_id`

管理员发布日志应包含：

- `admin.notice.save`
- 操作者用户名
- 通知 ID
- 通知标题
- 可见范围
- 置顶状态
- 新建/修改标识

禁止在日志中记录正文中的敏感信息或任何密码。

## 6. 自动验收命令

```bash
# 检查配置
.venv/bin/python manage.py check

# 确认模型没有遗漏迁移
.venv/bin/python manage.py makemigrations --check --dry-run

# 应用当前数据库迁移
.venv/bin/python manage.py migrate

# 执行通知模块测试
.venv/bin/python manage.py test notices --verbosity 2

# 执行完整回归测试
.venv/bin/python manage.py test --verbosity 1
```

预期结果：

- `check` 无错误
- `makemigrations --check --dry-run` 输出 `No changes detected`
- 通知测试全部 `OK`
- 阶段一和阶段二的全量测试全部 `OK`

## 7. 人工冒烟验收

1. 使用超级管理员进入 `/admin/`。
2. 新建一条公开通知，设置标题、正文，可选择置顶。
3. 退出 Admin，以匿名方式打开 `/` 和 `/notices/`，确认能看到公开通知。
4. 打开公开详情，确认正文和发布信息正确。
5. 新建一条内部通知。
6. 匿名访问 `/member/notices/`，确认跳转登录。
7. 使用已完成改密的成员登录，打开 `/member/notices/`，确认只能看到内部通知。
8. 使用匿名或成员访问 `/notices/<内部通知 ID>/`，确认返回 404。
9. 创建一个未完成改密的成员，访问 `/member/notices/`，确认先跳转 `/member/password/`。
10. 在 Admin 的通知列表检查范围筛选、置顶筛选和标题搜索。
11. 查看 `logs/django.log`，确认访问和发布事件存在且不含密码。

## 8. 完成门槛

以下任一项不满足，阶段二保持“未完成”：

- 任意自动测试失败
- 存在未生成的模型迁移
- 内部通知可以通过公开 URL 泄露
- 未改密账号可以绕过强制改密访问内部通知
- 普通成员可以进入通知 Admin
- 发布人没有自动记录
- 关键访问和发布日志缺失
