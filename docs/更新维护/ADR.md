# 架构决策记录

> **只记架构级决策**——影响多个模块、或者很难反悔的那种。业务功能改动不在这里
> （那些在 git 提交与 tag 里）。
>
> **本文件拥有**：平台级、跨模块的决策（日期／决定了什么／为什么／**否掉了什么**）。
> **初始选型的理由不在这里** → [`../原型设计/设计说明.md`](../原型设计/设计说明.md) §2，
> 那一份已冻结。**逐模块的由来** → 各 [`<app>/README.md`](../../accounts/README.md) 的「由来」节。
>
> 判断某条该写哪：**技术形态**（语言、框架、存储、错误形态、测试配置）→ 设计说明的「关键取舍」；
> **平台规则**（某件事全平台怎么保证、某个概念怎么表达）→ 这里；**只关乎一个模块** → 那个模块的 README。

**什么时候看**：想改一条平台级规则之前；好奇「当初为什么不是另一种做法」。

---

## 1. 什么时候加一条

| 加 | 不加 |
|---|---|
| 换框架、换存储、换通信方式 | 加一个业务功能 |
| 分层或模块边界调整 | 改一个算法实现 |
| 引入或去掉一个关键依赖 | 调参数、改界面 |
| 破坏兼容的数据格式变更 | 修 bug |
| **某条平台级规则的保证方式变了**（从约定变成数据库约束、从一个概念换成另一个） | 把某个开关的默认值改掉 |

> 拿不准就问一句：**这个决定半年后还会有人问「当初为什么」吗？** 会，就写。

## 2. 一条的写法

```markdown
### YYYY-MM-DD — 决定了什么

- **背景**：为什么需要做这个决定
- **决定了**：选了什么
- **没选**：否掉了什么、为什么不选
- **后果**：要跟着改什么、留下了什么代价
```

> **「没选」这一栏不要省。** 半年后你只会记得结论，不会记得当时否掉了什么——省掉它，
> 同一个讨论就会重来一遍。

### 2026-10-10 — 评审的「请假窗口」换成接单开关

- **背景**：评审人需要一种「这段时间先别派任务给我」的表达。原先的机制是一张请假表：两个时间点 + 事由，到点自动恢复。
- **决定了**：改成 `User` 上的两个布尔字段（初审、评审各一个开关），关掉后不被抽中、不进改派候选；**手上有未完成的任务时关不掉**；管理员在用户列表看得到谁关掉了、也能替人开关。
- **没选**：保留请假窗口并补上「未来某段时间不接单」的预约能力。那个能力要表达的其实是「现在收不收新任务」，用时间区间去逼近它的代价是一张表、一套登记／取消服务、一条后台屏，以及一个「到点自动恢复」的隐含承诺（而恢复还得有人确认它真的发生了）；抽人与改派本来也各自要做一次时间比较。
- **后果**：**丢掉了预约能力**——现在只能到时自己关（当时判断这个能力没人真用）。窗口表被删（迁移里既有加列也有删表，是这条流水线上少见的两头都动，回滚要**先反迁移再切旧 tag**，见 [`开发与部署.md`](开发与部署.md) §4.4）。历史审计行里的 `reviews.leave.*` 保留不动，新动作是 `reviews.availability.open` / `.close`。字段住在 `accounts`，规则住在 `reviews`——这条错位——**字段住在 `accounts`、规则住在 `reviews`**——登记在 [`reviews/README.md`](../../reviews/README.md) §1。

### 2026-10-10 — 审计「只追加」从约定落到数据库触发器

- **背景**：审计日志是「谁在什么时候动了什么」的底账，改动它等于篡改历史。此前只有后台的 `AuditLogAdmin` 在拦（禁增删改），脚本与 ORM 照样能改——「只追加」那时只是约定。
- **决定了**：迁移 `core.0003` 给审计表挂行级触发器 `core_auditlog_append_only`，`UPDATE` / `DELETE` 一律 `RAISE EXCEPTION`。逃生口只有两条（临时摘触发器、或 superuser 会话里 `SET session_replication_role = replica`），见 [`开发与部署.md`](开发与部署.md) §6。
- **没选**：**收数据库权限**。属主能 `REVOKE` 自己（实测收得动），但也**随时能 `GRANT` 回来**——收不掉的只是属主的 grant option，所以「收权限」拦得住误操作、拦不住恶意。真要收住得另建角色、把日常连接换成非属主账号，那是部署形态的改动，比一条触发器贵得多。
- **后果**：**有审计行的账号删不掉了**（`AuditLog.user` 是 `SET_NULL`，置空那一步被触发器挡住；后台点删除的页面结果是 500）——账号退场的正常口径改成**停用**。归档旧审计行也要走逃生口。挡不住的还有整表级与 DDL 级动作（`TRUNCATE`、`DROP TABLE`、整库恢复、`ALTER TABLE`）——那些靠备份与权限。

### 2026-10-10 — 项目组列表对全体登录成员可见

- **背景**：原先列表按「有没有组」分档：无组员只看得到一部分，组员看到的更多。
- **决定了**：`groups_visible_to` 改成「登录即全部」。想只看自己参与的组，用页面上的 `?mine=1` 筛选。
- **没选**：继续按有没有组分档。列表的用途是「社团里有哪些组、我想进哪一个」——**看不出别的组就没有比较可言**，而「我参与了哪些」是筛选能解决的问题，不该由可见性来做。
- **后果**：可见范围只管**列表**；**详情与项目书取件仍是 `can_view_group` 那道门**（含评审侧主张，几支取并集）。越权取件仍 403，与列表的放宽不是一回事。

### 2026-09（贯穿早期版本）— 有意排除的依赖

- **背景**：加依赖是单向门——一旦装进 `requirements.txt`，它会进锁文件、进部署环境、进许可清单。这个平台是社团规模、单机部署，容量与复杂度都该留给真正需要的东西。
- **决定了**：下面几个**有意不加**，理由记在这里，免得后人重复评估：

  | 没有它 | 为什么 |
  |---|---|
  | `djangorestframework` | 曾作为「为后续 API 预留」**空装着**（零路由、零视图），后按「不留不用的依赖」移除。要开放 API 时先引入，再按 [`接口.md`](接口.md) 登记 |
  | `tinycss2` | `bleach` 只在它的 `css` extra 里需要，本项目不用那部分 |
  | HTMX、富文本编辑器组件 | 交互以整页表单提交为主，页面脚本只做渐进增强；Markdown 在 textarea 里手写、服务端渲染（选型理由见 [`../原型设计/设计说明.md`](../原型设计/设计说明.md) §2） |
  | ffmpeg、对象存储 SDK | 不做视频转码、不切对象存储；直传 MP4 由 Nginx 直出并支持 Range |

- **没选**：把「以后可能需要」当成现在就装的理由。
- **后果**：真要引入时是**新决策**——按 §1 的判据再走一遍，别照着「反正以前想过」直接加。
