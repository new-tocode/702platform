# 许可

> **本文件只拥有一件事：分发义务的评估结论。**「用了哪些包、各是什么许可」是
> [`THIRD_PARTY_LICENSES/README.md`](../../THIRD_PARTY_LICENSES/README.md) 那张表跟着锁文件走，
> 本项目自身的许可是仓库根的 [`LICENSE`](../../LICENSE)——两处都不在这里重复。
>
> **为什么还留着这份文件**：本仓库是**公开的**，分发义务当下就成立，而「这些义务合起来意味着
> 什么」不是读 `requirements.txt` 能得出的——那是法律面的判断，代码里没有它的位置。

**什么时候看**：加依赖之前；对外分发或公开之前；有人问「这个能不能拿去用」。

---

## 1. 义务评估

**强传染（GPL／AGPL）没有。** 唯一的传染性许可是 **psycopg 的 LGPL-3.0**：

- 它是以**库的形式**被导入的（未修改其源码），所以是弱传染——分发时**随附 LGPL 原文并声明**即可；
- LGPL-3.0 另外要求使用者能**替换**该库：本项目是动态导入的 Python 包 + 随附的二进制轮子，满足；
- **所以本项目不必开源。** 注：`psycopg-binary` 内含静态链接的 libpq（PostgreSQL License，宽松），
  不改变上面的结论。

其余依赖都是宽松许可（BSD／MIT／Apache-2.0），**保留声明就够**。

## 2. 分发边界

自己几台机器之间传递**不触发**义务；**给第三方就触发**——这个仓库是公开的，所以义务**现在成立**，
`THIRD_PARTY_LICENSES/` 必须跟着仓库一起在。

构建与开发工具（`pip-tools`、`pip-audit`、Playwright 等）不在 `requirements*.txt` 里、
也不进部署环境，**不随交付物分发，故不附原文**。

> **有意不加的依赖**（DRF、HTMX、富文本编辑器、ffmpeg……）及其理由在 [`ADR.md`](ADR.md)——
> 那是架构决策，不是许可事项。
