# 接口

> **这份文件只拥有一件事：跨模块的 HTTP 口径。**「有哪些地址、每个地址什么门槛」**不在这里**——
> 地址读各 app 的 `urls.py`，门槛读对应视图（都只隔一层，且改名/加页时本来就要打开它们）。
> **具体字段、参数默认值与约束清单也不在这里**：以代码为准（见 [`../../CLAUDE.md`](../../CLAUDE.md) §2）。
>
> 为什么留着这一节：下面几条是**跨模块的约定**，散在三十几个视图里，没有任何一个文件装着它们。

**什么时候看**：加一个页面或地址之前；拿不准某个拒绝该是 403 还是 404；排查一个「怎么返回 302」
或「怎么没留日志」的越权。

---

## 拒绝与失败的形态

- **未登录** → 302 到 `accounts:login`（带 `next`）。
- **已登录，但缺资格／不是本人／缺对象级权限** → **403**（门槛经 `core.permissions.require`，
  或视图里直接 `PermissionDenied`）。
- **对象不存在、或不属于当前上下文** → **404**。
- **对 POST-only 视图发 GET** → **405**。

**业务拒绝不是 4xx。**服务层抛领域异常（`JoinRequestError` / `ReviewError` / `GroupManagementError`
等），视图翻成 flash 后 **302** 回列表页——浏览器拿到的是 302，不是 4xx。

**写操作一律 POST + CSRF。**表单页失败时重渲染 200、成功 302；**动作端点**（`@require_POST`）
不论成败都 302（PRG + flash），收到 GET 会 405。

**未改密账号**：`must_change_password=True` 时，除改密页与登出外的一切路径都 302 回改密页
（`config.middleware`，**连 `/admin/` 也不放行**）。

**越权取件的 403 是否留痕**：多数经 `require` 记一条 warning；**已知两处裸抛、不留日志**——
`projects:group_materials_download` 与 `reviews:complete`。排查越权尝试时记得这两支是静默的。

## 刻意为之的错位（grep 看不出来的）

这几条都是「看着像 bug，其实是设计」，改之前先想清楚：

| 位置 | 错位 |
|---|---|
| `accounts/file_views.gallery_file` | **读口不做归属过滤**——图册本来就在个人主页上给成员看；按 `profile=` 过滤的是**写口**（排序／改排布／删除）。别把写口的口径套到读口上 |
| `reviews` 的两条 `complete/` 路径 | 是**同一个视图**，门槛与表单由任务的 `stage` 决定；两条都保留只是为了不打断历史链接 |
| `equipment` 的归还 | **不查项目组归属**——被移出组的人仍要能还掉手里的设备，否则权限把人锁死了 |
| `discussion` 的建／删板块 | 只认 Django `is_superuser`（全站唯一把它当独立资格的地方），且**模板按钮与视图判定必须同源**，否则会出现「按钮在、提交 403」 |
| 项目组列表 vs 详情 | 列表**登录即列全部**（放宽的是列表），详情与三处受保护件取件仍是 `can_view_group` 那道门。**放宽列表不等于放宽取件** |
| `notices` 的成员页（通知详情、`message_go`、三个私信视图） | **越权一律 404**，不区分「不存在」与「不是我的」——本 app 刻意没有 `permissions.py`，也不引 `core.permissions`。要看的对象都按 `...=request.user` 取，取不到就是 404，所以这条路上一句 403 都不会出现 |
